## V1.5.2 修复证据（2026-10-09）

- **后台打开文件**：原逻辑在没有窗口时一律排入启动队列，但应用已经启动后不再消费此队列。现在启动前排队、启动后复用或创建窗口并立即交付文件；Dock 重开隐藏窗口不再创建冗余窗口，展示窗口时显式取消最小化。
- **滚动回顶**：修复前的隔离 WKWebView 诊断中，滚动比例约 0.60 在相同内容重载后降为 0；生产 FileWatcher 的纯修改时间通知也触发回顶。现在相同内容只刷新磁盘指纹、不重建 DOM；真正内容变化时捕获读取完成后的当前滚动比例，并保护过期动画帧回调不干扰其他标签或新滚动。
- **保存安全**：异步读取按标签请求令牌去重；标签关闭、另存为、保存及更新版本变化后拒绝旧结果。本地未保存编辑或读取期间的新编辑不被自动重载覆盖；仅实际磁盘内容变化才报冲突。显式放弃编辑要等读取成功后才清除修改标记；失败保留内容。
- 自动化套件只使用合成临时 Markdown 和独立内存设置，不操作用户文档。生命周期套件使用生产 AppDelegate 和记录窗口桩，**不是** Finder/LaunchServices 到生产窗口/原生桥的完整端到端测试；安装后的实机验证另列如下。
- **安装后 Finder 实机检查**：按用户要求替换 `/Applications/MoRead.app` 后，在 Finder 实际双击仓库 `tests/fixtures/standard.md`，冷启动显示正确文件路径、正文及 `MoRead v1.5.2`。关闭测试窗口后切回 Finder，核对同一应用进程仍运行、WindowServer 记录均不在屏幕上；再次双击该文件，在同一进程内打开正确文档而非欢迎页。CUA 若在关闭窗口后直接重新激活应用，会触发 Dock 重开，因此热启动测试关闭后仅切回 Finder，不依赖重新激活来触发窗口创建。未修改 Markdown 内容；最近文件记录正常更新。

## V1.5 / V1.5.1 关键场景记录

以下保留原功能记录；套件已在 V1.5.2 重跑，PDF 独立文本提取和页面视觉检查仍为 2026-10-07 的历史验证。

### 1. 阅读模式 vs 编辑模式严格防篡改验证
- 打开文件默认为只读阅读模式，正文 `contentEditable="false"`，源码 `textarea.readOnly = true`。
- 任务复选框在只读模式下阻止事件触发，代码复制按钮正常工作，代码编辑框禁止聚焦和输入。
- 阅读模式直接点击超链接调用系统默认浏览器打开；编辑模式普通点击定位光标，Cmd+点击打开链接。
- 点击右上角“编辑”按钮切换至编辑模式；有未保存修改时退出编辑模式弹出原生确认框（保存并退出/放弃修改/取消）。

### 2. 保存安全与原文保护
- 只查看或切换模式时不触发写盘；无修改按 Cmd+S 不触发写盘。
- 渲染保存时通过 Turndown 规则拦截并还原：
  - 自动还原 `mored://local?path=...` 为原始路径，防止专有协议泄漏到 Markdown。
  - 自动剥离 `<mark class="search-highlight">` 搜索高亮标签，防止搜索污染文档内容。
- 文件读取时检测并记录 UTF-8 BOM 及 CRLF 行尾；写入时通过 NativeBridge 还原对应的 BOM 与 CRLF。

### 3. 多标签页与独立窗口快捷键规范
- 同一窗口内打开多个文档以标签页管理，每个标签页独立维护阅读滚动条、修改历史、编辑模式与草稿。
- 遵循 macOS 原生习惯：`Cmd+T` 新建标签页；`Cmd+W` 关闭当前标签（有未保存修改时确认）；`Cmd+N` 打开独立的原生应用窗口。
- 重复打开已打开的文件时，直接聚焦已有标签页，不重复加载亦不丢失未保存修改。
- V1.5.1 实际复现：渲染模式输入只更新 DOM 与修改标记，离开标签时未回写 `rawContent`，返回后编辑消失。现仅对已修改的渲染文档在切换前执行 `htmlToMarkdown` 缓存；未修改的原文保持不动。新增真实 WebKit 检查正文、代码内容、代码语言、公式、源码、修改标记与其他文档隔离。跨标签撤销历史不在此次验证内。

### 4. 外部修改冲突与本地恢复草稿
- `FileWatcher` 支持多文件独立监听字典；本地写盘时主动抑制自触发事件。
- V1.5.2 收到文件通知后先读取并核对内容，只有实际磁盘内容变化且本地存在未保存修改时才弹出冲突横幅并暂停自动保存；属性通知不再误报。
- 编辑过程中每 1.5 秒自动防抖保存本地草稿到 Application Support 恢复目录；下次启动或异常恢复时弹窗提示恢复/丢弃。

### 5. 单文件打开与性能优化
- 移除了打开单文件时对上级整个目录树的深度无界递归扫描。
- 原生 `scanDirectory` 限制 `maxDepth: 2`（单次上限 500 项），减少单次扫描范围；不将这一限制解释为所有大型目录或实机场景均不会超时。

### 6. 纯净 PDF 导出与设置分类
- 原生菜单项“导出为 PDF…”(`Cmd+Option+P`)。
- 原实现 `WKWebView.createPDF` 捕获完整页面，不能凭 `@media print` 推断分页。用户提供的 PDF 经 `pdfinfo` 检查只有 1 页、1470 × 3216 点，已渲染确认是整页长文档。
- 改用自包含、无脚本的只读 HTML 快照与独立 WKWebView；`NSPrintInfo` 固定 A4 纵向、四边 36 点边距，`printOperation` 自动分页。异步打印回调切回主线程，避免 AppKit 后台回调关闭窗口崩溃。
- 快照读取当前未保存源码/渲染编辑，但不替换主编辑区、不重置模式/滚动/光标、不标记 Markdown 已保存。目标 PDF 仅在打印结果有效后原子写入，失败返回失败而非提前返回成功。
- 移除应用界面、复制与代码编辑控件；字体及图片就绪后打印，离线/失败图片显示说明；白底版式不受主界面深色、字号或阅读宽度影响。
- 修复中文/空格本地图片路径被重复 URL 编码；未命名文档也应用远程图片拦截，不再在 PDF 导出时强制启用远程图片。
- 实际导出：未保存源码与未保存渲染版本各 9 页 A4；短文档、空文档、缺失图片各 1 页。逐项检查 140 行代码、100 行表格、35 个段落与文末标记，所有页尺寸均为约 595 × 842 点且没有意外空白页。
- 另用 pdfplumber 独立核对全部标记及文本距纸张边界至少 35 点；Poppler 渲染全部长文档页面，并查看跨页代码/表格、首页、末页、短文档与失败图片说明，未发现文字裁切或应用控件泄漏。样例见 [分页测试.pdf](output/pdf/分页测试.pdf)。
- 设置面板分类清晰，划分为“阅读与视图”、“保存与安全”、“网络与隐私”三个清晰区块，移除了冗余提示文案。

## 覆盖边界

- 旧 WebKit 套件的 `exportPDF` 是空桩，不能支持原 PDF 分页结论；本次新增专用套件实际执行生产 PDF 打印路径。
- Finder 冷启动及后台无可见窗口打开已按上述合成 fixture 实机验证；不代表所有文件关联和同步目录场景已覆盖。原生保存面板取消、窗口拖动、最小化恢复、跨标签撤销及全部 V1.5 新增功能未在本轮完整验证。
- 当前 `Cmd+T` 新建标签、`Cmd+N` 新建窗口，与早先用户提出的 `Cmd+T` 新建窗口不同；本次保持不改，待用户确定快捷键。
- 用户原 PDF 未改动。若要按相同原文重新导出，需要在修复版应用打开原 Markdown 文件；不会由 PDF 逆向重建原文。
