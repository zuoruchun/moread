# MoRead 缺陷修复与验证

最后更新：2026-10-07

## 当前结论

本次 V1.4.0 已构建并安装到 `/Applications/MoRead.app`。正式发行状态以 [GitHub Release](https://github.com/zuoruchun/moread/releases/tag/v1.4.0) 为准。V1.3.0 的源码、DMG 和 ZIP 均保留在 `dist/`。

- 渲染模式中可以直接修改代码块语言和内容；彩色显示层与纯文本输入层同步，不重建输入框或移动光标。
- 补充 Bash 自定义命令、参数和数字高亮，仍保留字符串、注释、变量和关键字规则。
- 复制及保存读取当前代码，而非旧复制缓存；保留缩进和尾部空行，遇到代码内的反引号围栏使用更长的 Markdown 围栏。
- 修复编辑层被父元素鼠标设置挡住的问题，并加入点击命中检查。

## 验证结果及边界

- `npm test`：49 项单元测试通过，包括 200 行代码连续三次往返、未知语言、XSS 转义，以及长围栏、波浪线围栏、列表内围栏和未闭合围栏中的数学样式文本。
- `npm run test:native`：27 项原生测试通过；该结果不代表真实 Finder、窗口拖动或整套应用生命周期已重新测试。
- `npm run test:renderer:bridge`：36 项实际 WebKit 交互检查通过，文件读写和目录扫描使用生产 `NativeBridge`，设置在内存中，文件限定临时测试目录。覆盖代码编辑、语言修改、着色、中文输入法事件、复制、保存、撤销/重做、尾部空行、源码往返、粘贴、长行滚动和点击命中。
- 已安装应用实测：点击代码框编辑中文代码并保存；把 `python` 改为 `py`，源码中语言和内容正确，返回渲染后继续显示彩色代码。只修改专用测试文件，没有修改用户原来的文档。
- 最终应用签名、DMG 验证和 DMG/ZIP SHA-256 校验通过。构建仍有既存 Vite 大包及 CJS API 警告，未为此扩大依赖或重构范围。

## 尚未解决的问题

单独打开文件后，自动扫描其目录在实机中出现超时。线程采样显示后台线程阻塞于 `contentsOfDirectoryAtURL` 内的系统 `open` 调用；通过“文件 → 打开文件夹”明确选择测试目录后，实际文件列表恢复正常。暂不能仅凭线程栈确认系统隐私权限是唯一原因；这不是代码编辑回归检查的通过项。本次未更改系统隐私权限，下一步应单独处理目录访问场景和授权提示。
